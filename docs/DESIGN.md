# 설계 문서 (Design) — Circle Camera

> 1차 타겟: **웹 프로토타입**. 컨셉 검증이 목적이며, 검증 후 네이티브로 확장.

---

## 1. 문제 / 컨셉

여행 릴스에는 "화면(또는 손가락 O, 렌즈 앞 링)에 동그라미를 만들고, 멀리 있는
피사체(달·탑·아치·사람)를 그 동그라미 안에 딱 맞춰 찍는" 구도가 자주 등장한다.
이 작업은 지금은 **순전히 수동**이라, 맞추기 번거롭고 셔터 타이밍에 흔들린다.

이 앱은 그 과정을 돕는다:

1. 화면에 원(타겟 도형)을 띄운다 → 사용자가 위치/크기 조절
2. 피사체를 원 안에 들어오게 카메라를 움직인다
3. 앱이 **얼마나 맞았는지 실시간 피드백** → 다 맞으면 **자동 촬영**

---

## 2. 사용자 & 사용 시나리오

- **주 사용자:** 여행/일상 숏폼(릴스·틱톡·쇼츠) 크리에이터, 감성 사진 좋아하는 일반 사용자
- **대표 시나리오:**
  - 노을 진 하늘의 해를 원 안에 가두어 한 컷
  - 멀리 보이는 탑/등대를 원 안에 정확히 배치
  - 친구를 원 안에 세워두고 "딱 맞으면" 자동 촬영(손 안 흔들림)

---

## 3. 기능 레벨 (단계적 구현)

**촬영은 항상 사용자가 직접(수동 셔터)** 한다. 인식/정렬 표시는 *자동 촬영 트리거가 아니라*
"맞춰가는 가이드" 용도의 시각 피드백일 뿐이다.

| 레벨 | 이름 | 내용 | 단계 |
|---|---|---|---|
| **L1** | 수동 오버레이 | 원을 드래그·핀치로 배치, 수동 셔터, 저장/공유 | MVP 필수 |
| **L2** | 정렬 가이드 | 피사체 실시간 인식 → fit 게이지/방향 힌트(시각 피드백). **셔터는 수동** | 차별점 |
| **EDIT** | 후보정 모드 | 찍은/고른 사진에 원 프레이밍·크롭·효과 적용 후 내보내기 | MVP 포함 |
| **L3** | 스마트 검출 | 풍경 속 둥근 사물 자동 검출 → 원 제안/스냅 | 확장 |

자세한 일정은 [ROADMAP.md](ROADMAP.md) 참고.

---

## 4. 화면 흐름 (Flow)

두 개의 진입점: **촬영(Capture)** 과 **후보정(Edit)**.

```
[홈]
 ├─[촬영 모드]
 │     [권한 요청] → [카메라 화면]
 │                      │  ┌─ 원 배치/크기 조절 (드래그·핀치)
 │                      │  └─ 가이드 토글 (그리드, 비율 9:16 등)
 │                      ▼
 │                 [피사체 정렬]  ← fit 게이지/방향 힌트 (가이드일 뿐, 자동촬영 X)
 │                      ▼
 │                 [수동 셔터로 캡처]
 │                      ▼
 │                 [프리뷰] → 저장 / 다시찍기 / 공유 / "보정으로 보내기"
 │
 └─[후보정 모드]
       [사진 선택] (카메라 결과 또는 파일에서 불러오기)
            ▼
       [원 프레이밍·크롭·효과 편집]  ← 원 위치/크기 조절, 비율, 마스크/비네팅 등
            ▼
       [내보내기] → 저장 / 공유
```

## 5. 기술 설계 (웹 프로토타입)

### 5.1 스택

- **렌더링:** 순수 HTML/CSS/JS 또는 경량 프레임워크. 의존성 최소화.
- **카메라:** `navigator.mediaDevices.getUserMedia({ video: { facingMode: 'environment' } })`
- **오버레이/그리기:** `<canvas>` 2D (원·게이지·그리드). 프리뷰는 `<video>` 위에 캔버스 레이어.
- **피사체 인식(L2):**
  - 1순위: **MediaPipe / TensorFlow\.js** — `coco-ssd`(객체 bbox) 또는 selfie/segmentation 모델
  - 사람 위주면 segmentation, 일반 피사체면 saliency/object detection
- **둥근 사물 검출(L3):** **OpenCV\.js** Hough Circle Transform
- **캡처:** `canvas.drawImage(video)` → `canvas.toBlob()` → 다운로드 또는 **Web Share API**(`navigator.share`)

### 5.2 모듈 구조

```
CameraService      카메라 스트림 시작/정지, 해상도·후면카메라 선택
OverlayRenderer    원, 게이지, 그리드, 정렬 피드백 그리기 (requestAnimationFrame)
TargetShape        원의 위치(cx,cy)·반지름 r·상태(idle/near/good) 보관 — 촬영·편집 공용
DetectionService   N프레임마다 피사체 인식 → bbox/mask/centroid
MatchEngine        TargetShape vs 피사체 → fit score, 방향 힌트 (가이드용, 자동촬영 X)
CaptureService     수동 셔터로 프레임 캡처 → Blob → 저장/공유 / 편집으로 전달
EditService        사진 로드(카메라 결과·파일) → 원 프레이밍/크롭/효과 → 내보내기
HapticService      GOOD 상태 등 가벼운 진동(navigator.vibrate) (선택)
UIController       제스처(드래그·핀치), 토글, 셔터 버튼, 모드 전환(촬영/후보정)
```

### 5.3 정렬 가이드 로직 (L2)

피사체의 중심 `(px, py)`, 반경 `pr`(또는 bbox 기반 등가 반경)을 구하고,
타겟 원 `(cx, cy, r)`와 비교해 **fit 점수와 방향 힌트만** 만든다. 자동 촬영은 없다.

```
centerErr = distance((px,py),(cx,cy)) / r            // 0이면 완벽
sizeErr   = abs(pr - r) / r                           // 0이면 크기 일치
score     = clamp(1 - (w1*centerErr + w2*sizeErr), 0, 1)   // 0~1

// 시각 피드백 상태 (가이드용)
if score >= 0.9: state = GOOD   (원 초록, "지금!")
elif score >= 0.6: state = NEAR (원 노랑 + 방향 화살표 "←/위로", 크기 "더 가까이/멀리")
else: state = IDLE (원 회색)

// 셔터는 항상 사용자가 직접 누른다. score는 표시만.
```

- 가중치 예시: `w1 = 0.6`(중심), `w2 = 0.4`(크기)
- GOOD일 때 가벼운 햅틱/하이라이트로 "지금 누르세요" 힌트(선택). 촬영은 강제하지 않음.
- 인식이 흔들려도 셔터와 무관하므로, 정밀도 요구가 낮아 구현 부담이 작다.

### 5.4 성능

- 인식은 **매 프레임이 아니라 2~4프레임당 1회**(예: 10~15fps) → 오버레이는 60fps 유지
- 모델은 가능한 한 작은 것(quantized) 사용, 첫 로드 시 프리워밍
- 무거운 작업은 가능하면 **Web Worker / OffscreenCanvas**로 분리

### 5.5 후보정 모드 (EDIT)

현장에서 못 맞췄거나, 기존 사진을 같은 무드로 만들고 싶을 때를 위한 사후 편집.

- **입력:** 촬영 결과 Blob, 또는 `<input type="file" accept="image/*">`로 불러온 사진
  (웹은 갤러리 직접 접근이 막혀 있어 파일 선택 방식 사용)
- **편집:** 사진 위에 원을 드래그·핀치로 배치, 비율 프레임(9:16/1:1/4:5) 적용
- **효과(선택):** 원 밖을 어둡게/흐리게(마스크·비네팅), 원 안만 강조, 테두리 스타일
- **내보내기:** 편집 결과를 `canvas`로 렌더 → `toBlob()` → 다운로드 / `navigator.share`
- **재사용:** 촬영 모드의 `TargetShape`·`OverlayRenderer`를 그대로 공유(정지 이미지 위에서 동작)

## 6. UI 요소

- **원(타겟):** 반투명 외곽선. 상태별 색 — 회색(idle) / 노랑(near) / 초록(good)
- **fit 게이지:** 원 둘레를 따라 채워지는 링, 또는 하단 바 + 퍼센트 (가이드 표시)
- **방향 힌트:** near일 때 "←/위로", 크기 "더 가까이/멀리" 화살표
- **컨트롤:** 수동 셔터, 그리드 토글, 비율(9:16/1:1/4:5), 전/후면 전환, 모드 전환(촬영↔후보정)
- **후보정 컨트롤:** 사진 불러오기, 원 배치/크기, 비율, 효과(마스크/비네팅), 내보내기
- **제스처:** 드래그=원 이동, 핀치=원 크기, 더블탭=중앙 리셋
- **피드백:** good 상태일 때 가벼운 진동 + 링 하이라이트 ("지금 누르세요" 힌트)

---

## 7. 데이터 / 저장

웹 프로토타입에서는 서버·계정 없음(로컬 only).

- 촬영 결과: `Blob` → 다운로드(`<a download>`) 또는 `navigator.share`
- 설정(원 기본 크기, 자동촬영 on/off 등): `localStorage`
- **제약(웹):** "사진 앱 갤러리에 바로 저장"은 OS처럼 매끄럽지 않음 → 다운로드/공유 시트로 대체.
  이 부분이 네이티브 전환의 주요 동기 중 하나.

---

## 8. 권한 / 프라이버시

- 카메라 권한 명시적 요청, 거부 시 안내 화면
- **모든 처리는 온디바이스(브라우저 내)** — 영상/사진을 서버로 전송하지 않음
- 인식 모델도 클라이언트에서 실행

---

## 9. 웹 프로토타입의 한계 & 네이티브 전환 기준

| 항목 | 웹 | 네이티브(iOS) |
|---|---|---|
| 갤러리 저장 | 다운로드/공유로 우회 | 매끄러움 |
| 피사체 분리 품질 | TF.js/MediaPipe(보통) | Vision foreground mask(우수) |
| 카메라 제어(노출/포커스/줌) | 제한적 | 풍부 |
| 성능/배터리 | 보통 | 우수 |

➡️ **전환 트리거:** 웹에서 "정렬 어시스트 + 자동촬영" 컨셉이 사용자에게 먹힌다고
확인되면, 그때 iOS 네이티브로 품질·저장 경험을 끌어올린다.
