# 로드맵 (Roadmap)

검증 우선. 가볍게 만들어 반응을 본 뒤 깊이를 더한다.

## 마일스톤

### M0 — 설계 (현재)
- [x] 아이디어 평가, 경쟁 조사
- [x] 제품/기술 설계 문서화
- [ ] 열린 질문 결정(도형 범위, 피사체 정의, 자동촬영 감도, 앱 이름)

### M1 — L1 수동 오버레이 (웹 MVP)
- [ ] 카메라 프리뷰(후면, 9:16)
- [ ] 드래그·핀치로 움직이는 원 1개
- [ ] 그리드/비율 토글
- [ ] 수동 셔터 → 캡처 → 프리뷰 → 다운로드/공유
- [ ] `localStorage` 설정 저장
- **완료 기준:** 폰 브라우저에서 원 맞춰 한 컷 찍어 저장 가능

### M2 — L2 정렬 어시스트 (차별점 핵심)
- [ ] 피사체 실시간 인식(TF.js/MediaPipe)
- [ ] fit 점수 게이지 + 상태별 원 색(idle/near/locked)
- [ ] 안정성 판정 → 자동 촬영 + 햅틱/사운드
- [ ] 인식 throttle, 60fps 오버레이 유지
- **완료 기준:** 피사체를 원에 맞추면 알아서 찍힌다

### M3 — L3 스마트 검출 (확장)
- [ ] OpenCV.js Hough Circle로 둥근 사물 검출 → 원 제안/스냅
- [ ] 도형 변형(다각형/별/하트), 다중 원

### M4 — 네이티브 전환 검토
- [ ] 웹에서 컨셉 검증되면 iOS(SwiftUI+Vision)로 품질·저장 경험 강화

## 결정한 사항

- 1차 플랫폼: **웹 프로토타입**
- 시작 범위: **설계 문서 먼저**, 이후 M1부터 구현

## 리스크 메모

- 기능이 얇아 복제되기 쉬움 → **자동 매칭 UX의 완성도**가 방어선
- 리텐션 약함 → 템플릿/챌린지/공유 루프로 "다시 열 이유" 설계 필요
- 단품 카메라 앱 수익화 난이도 → 프리미엄(도형팩/AI보정) 구조 사전 고려
